# D3-mini / D3-flash 调优试验结果

本轮是独立新样本上的小规模试验，不是旧测试重跑，也没有修改模型权重、精度或原生计算。
提示与阈值只由开发集选择，留出集不参与调优；仅直接筛选，不调用 reranker。

独立审计通过：22,050 次有效调用，218 个完整块，零失败/超时；2083 个旧证据文件保持不变。调用按阶段：`{"warmup": 1664, "dev": 3960, "holdout": 4138, "performance": 12288}`。

## 结论与建议

**同一套调优方法适用，但本轮没有找到让两款模型质量与速度同时普遍提升的统一配置。**
以下为基于本次审计数据的解读；后面的完整表格保留所有档位与两轮数据。

1. **分类保留原提示。** 两者在开发集都选中简短提示，但独立留出集没有提升：
   mini Accuracy 87.94%→87.66%，flash 87.66%→87.66%；macro-F1 也未提高，配对区间均跨零。
   不能用开发集的改进替代留出集结果，也不能把新样本分数与旧报告直接相减。
2. **mini 的证据阈值 0.45 是待复验候选。** 池宏 Recall 70.71%→73.39%，
   差值 95% CI 为 +0.86～+4.72 个百分点；池宏 F1 50.18%→51.50%，差值区间
   -0.03～+2.88 个百分点，尚不能确认稳定 F1 提升。Precision 基本不变，
   候选级 Accuracy 64.39%→64.23%，保留片段 333→348，漏光率不变。
   这是召回与保留数量的权衡，不是全面准确率提升，也不会降低模型调用次数。
3. **flash 的证据筛选暂保留原生 choice。** 开发集选择未找到符合约束且优于原方案的候选，
   留出直接复用原方案响应；表中的零差异不是两次独立运行证明了确定性。
4. **运行时保留 threads2 / seq32 / tokens32768 / window2ms。** threads1 没有普遍收益；
   compact 多数档位无提升或略慢。mini 分类 n16 的 compact 合并吞吐比为 1.109，
   但两轮分别 31.45/39.60 RPS，默认为 26.31/39.62 RPS，不能解释为稳定约 11% 提速；
   它也没有超过默认 n8 的 37.33 RPS。所有测过的运行时与并发档位均未发现判断翻转。
5. **按场景选并发，不统一追求高 n。** 本轮分类负载默认 n1→n8，mini 14.46→37.33 RPS
   （2.58 倍），flash 14.34→25.93（1.81 倍）；对应 P95 70.87→229.28 ms、
   71.45→323.45 ms。n16 不再更好。证据 n1→n16 只增至 1.35/1.12 倍，
   P95 却从 111.40/161.09 ms 升至 1213.16/1642.75 ms，不适合直接作为低延迟默认值。

性能测试使用开发集选出的质量配置：分类均为 concise，mini 证据为原提示加 0.45，
flash 证据为原生 choice。因此上述并发数字不能直接拼接成“原分类提示已验证的最优部署”。
恢复原提示后的 n4/n8 与实际业务 SLA，需要下一轮单独验证。

**下一步优先级：** mini 先扩大业务证据留出集，验证 0.45 阈值对召回、误收和下游上下文量的影响；
两款模型共用按输入长度分组的合批研究方案，并记录等待上限和尾延迟。当前证据负载 n8 的实际平均
批量仅 mini 1.21、flash 1.12 条，而分类是 4 条，值得继续定位合批效率；这仍是研究方向，
不是已证明的修复。暂不继续盲扫 CPU 线程数，不改生产配置，也未自动启动下一轮。

## 并发与运行时

单张 A100-PCIE-40GB、8 CPU、96 GiB 容器上限，固定 readiness 镜像、BF16 backbone / FP32 readout。
三个部署均独立装载后预热；模型间反转两个候选部署的次序，但不是随机多次冷启动实验。
- baseline：threads2、seq32、tokens32768、batch window 2 ms。
- thread1：仅 threads 与 OMP_NUM_THREADS 改为 1。
- compact：threads2、seq8、tokens8192、batch window 2 ms。

每任务 128 个开发集完整输入，每档两轮，第二轮并发档位反序；每格共 256 次尝试，独立输入仍只有 128 个。
性能子集最长：分类 433 token，片段 3,765 token。完整质量留出含更长输入，不能据此声称超长片段容量。
RPS=有效请求/两轮真实 wall 之和；P95/P99 对合并请求计算，不平均百分位。延迟包含服务端排队与鉴权 HTTP，
不含客户端等待空闲槽位和冷启动。是闭环短程压力，不是开放流量、长期 SLA 或业务容量承诺。

## 审计与解释边界

逐文件检查实际换行记录、输入/请求哈希、原生概率读出、一次调用、块内在途上限与块间无重叠，独立重算统计和开发集选择。
检查选择文件早于留出请求、源文件不变、旧证据不变、原评测容器 ID/镜像/命令恢复。
响应保留原生 answers/usage/meta 与完整响应哈希，未保留 HTTP 原始字节；可以重验原生答案，但不声称重建原始响应字节。
代理机三只保护服务身份由外部 SSH 单独前后核验，不由纯离线审计证明。
未改权重、未量化、未增加 CPU/GPU 资源、未使用结果缓存；没有运行 Clef 或重跑旧报告。
公开数据是否曾进入模型训练未知；本轮也不是 产品 线上真实业务质量验收。未修改生产模型绑定。
每档仅两轮，不能把请求数当作独立的性能试验次数，也不能将小幅吞吐差异直接认定为稳定提升。
运行时收益目前只在固定性能子集验证，若采用新部署还需要完整长输入质量回归与更长压力测试。
