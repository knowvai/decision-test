# 端到端问答测试：方法与逐次结果

本附录对应[文章](../README.md)的端到端部分，与前文 MASSIVE 分类、T2Ranking 片段筛选是不同的实验，不合并计算得分。

## 测试安排

题目依据测试知识库构造，共 30 题：12 题自然语言问法、12 题法规及条号定位、6 题知识库无法提供目标答案的问题。它们不是抽样的生产流量，也不足以代表全部法律问答。问题、目标条文或拒答标准见 [results.json](results.json) 的 `questions`。

每套主 LLM 服务下，两种配置各跑两轮，每轮 30 次，共 60 次；两套服务合计 **240 次正式请求**。这些请求来自同一组题目的重复测试，不能视为 240 个独立问题。

正式测试前完成预热。正式轮次采用按题型分层的五题分块安排，每轮两种配置先执行的次数相等；第二轮反转每题的先后顺序，两轮之间间隔 600 秒。外层问答逐个执行，片段筛选内部允许并发。每套主模型内采用配对对照，两套主模型服务分别测试；没有将不同时期的历史请求拼入本轮。

正式请求全部计入汇总，包括慢响应、回退和质量未通过的回答。240 次均返回 HTTP 200，应用记录的模型调用未出现失败；HTTP 成功不代表回答正确。

## 模型与流程

| 项目 | 内网组 | 阿里云组 |
|---|---|---|
| 主 LLM | `Qwen3-30B-A3B-Instruct-2507` | `qwen3.6-35b-a3b` |
| 主 LLM 部署 | 2 × A100-PCIE-40GB，BF16，TP=2，vLLM 0.31.0 | 服务方管理，未控制底层硬件与模型修订版本 |
| 决策模型 | D3-mini，原生 System One 接口 | 同一个 D3-mini 服务 |
| 决策模型部署 | 额外 1 × A100-PCIE-40GB，vllm-srun 0.2.0 | 同左 |
| 主 LLM 生成配置 | 非思考调用，temperature=0.1 | `enable_thinking=false`，temperature=0.1 |
| 主 LLM 前缀缓存 | 保留调优后的开启状态 | 服务端策略未控制，响应未报告 cached tokens，不能当作零命中 |

两套主 LLM 均分别运行以下配置：

- **LLM 模式**：路由、分批片段筛选、充分性检查、分解、检索规划和生成均沿用原有 LLM 实现。
- **接入 D3**：仅替换路由与片段筛选。路由使用 Noul 判断是否检索、Choice 判断问题等级；置信度保护触发时回退到原有 LLM 路由。筛选对每个候选片段独立调用 Choice，在 keep/discard 中选择，不按概率阈值筛选，不使用共享上下文。其余模型调用仍使用该组主 LLM。

两种配置的筛选并发上限均为 10。LLM 的分批筛选与 D3 的逐片段调用有不同的提示词和调度方式，因此结果衡量的是实际接入方案，不能单独归因于模型架构。增加 D3 也增加了一张 GPU；本实验不比较相同总算力下的效率、成本或并发容量。

应用版本、知识库文档版本和检索设置保持一致。应用镜像与 D3 权重的摘要见 `results.json` 的 `deployments`。应用问答缓存、上下文缓存、D3 结果缓存、引用高亮和独立 reranker 均关闭。Embedding 沿用原有远端 `Qwen/Qwen3-Embedding-0.6B` 服务，所以内网组并非全链路离线部署。

| 回退请求数 / 正式请求数 | LLM 模式 | 接入 D3 |
|---|---:|---:|
| 内网组 | 0/60 | 16/60 |
| 阿里云组 | 1/60 | 16/60 |

D3 组的回退发生在路由置信度保护；阿里云 LLM 组的一次回退发生在问题分解的结构化输出处理。它们均保留在正文的耗时与质量统计中。

## 各环节耗时

以下每格均为 **60 次完整问答**的平均耗时，单位秒。某次请求没有执行的环节按零计入分母；一题发生多轮执行时累计该题各轮耗时。相对变化为 `(接入 D3 / LLM 模式 - 1) × 100%`，用未四舍五入的均值计算。

带 * 的两个节点由不同模型执行；其余模型调用仍使用各组主 LLM。D3 组必要的 LLM 路由回退也计入路由节点。

**内网 Qwen**

| 环节 | LLM 模式 | 接入 D3 | 耗时变化 |
|---|---:|---:|---:|
| 完整问答 | 10.752 | 6.092 | -43.3% |
| 路由 * | 0.627 | 0.254 | -59.5% |
| 问题分解 | 1.285 | 1.155 | -10.2% |
| 检索 | 1.292 | 1.322 | +2.3% |
| 片段筛选及调度 * | 4.862 | 1.231 | -74.7% |
| 充分性检查 | 1.673 | 1.262 | -24.6% |
| 生成及其他服务端开销 | 0.950 | 0.807 | -15.1% |
| HTTP/传输差额 | 0.062 | 0.062 | -0.2% |

**阿里云 Qwen**

| 环节 | LLM 模式 | 接入 D3 | 耗时变化 |
|---|---:|---:|---:|
| 完整问答 | 9.596 | 7.605 | -20.7% |
| 路由 * | 0.886 | 0.359 | -59.5% |
| 问题分解 | 1.936 | 2.005 | +3.5% |
| 检索 | 1.554 | 1.915 | +23.2% |
| 片段筛选及调度 * | 3.112 | 1.233 | -60.4% |
| 充分性检查 | 1.337 | 1.363 | +2.0% |
| 生成及其他服务端开销 | 0.699 | 0.656 | -6.2% |
| HTTP/传输差额 | 0.071 | 0.074 | +4.6% |

完整问答时间由客户端计时，从发起请求到完整响应接收结束。节点时间取应用记录的实际经过时间，不将并发子调用的时长相加。检索节点包含检索规划等工作，并非单次向量查询耗时。

应用的筛选节点内还会串行执行充分性检查。这里将所记录的充分性模型调用耗时单独拆出，剩余部分记为“片段筛选及调度”，包含筛选、任务调度与结果处理。“生成及其他服务端开销”是服务端总耗时扣除已记录节点时间后的差额，不能当作纯生成模型耗时；“HTTP/传输差额”是客户端总耗时减去服务端时间，也不能当作纯网络延迟。各项在未四舍五入时加总等于完整问答时间。

| 统计 | 内网 LLM | 内网接入 D3 | 变化 | 阿里云 LLM | 阿里云接入 D3 | 变化 |
|---|---:|---:|---:|---:|---:|---:|
| 完整问答中位数，60 次 | 10.422 | 5.554 | -46.7% | 8.478 | 6.461 | -23.8% |
| 第一轮均值，各 30 次 | 10.378 | 6.095 | -41.3% | 9.953 | 7.740 | -22.2% |
| 第二轮均值，各 30 次 | 11.126 | 6.090 | -45.3% | 9.239 | 7.470 | -19.1% |

两轮方向一致是本组重复测试的观察，并非对任意问题、服务负载和部署条件的统计保证。

### 共用环节为何也会变化

| 执行量，60 次问答累计 | 内网 LLM | 内网接入 D3 | 阿里云 LLM | 阿里云接入 D3 |
|---|---:|---:|---:|---:|
| 检索节点执行次数 | 82 | 74 | 74 | 74 |
| 问题分解模型调用次数 | 82 | 74 | 75 | 74 |
| 充分性检查模型调用次数 | 56 | 46 | 46 | 46 |
| 主 LLM 调用总次数 | 588 | 326 | 560 | 327 |
| D3 调用总次数 | 0 | 794 | 0 | 793 |

调用数来自应用记录的模型调用，不是底层 SDK 的全部 HTTP 尝试数；一次 D3 路由调用含两道判断。调用次数也不等于计算量或费用。

内网组的问题分解和充分性检查总耗时减少，伴随着执行次数减少。每题首轮分解调用的平均耗时则为 0.931s 与 0.935s，基本相同。生成和充分性检查还受入选证据、输入输出长度影响。因此，共用环节的总时间变化不能直接解释为同一个 Qwen 模型运行得更快。

内网组保留前缀缓存，执行顺序与缓存状态仍可能影响结果。交替次序和第二轮反转只能降低顺序偏差，不能完全消除它。现有逐次记录未提供缓存命中 token 数，无法精确分离这些影响。[vLLM 官方说明](https://docs.vllm.ai/en/latest/features/automatic_prefix_caching/)中的前缀缓存复用作用于相同前缀的预填充计算，也不等于复用完整答案。

从各环节均值相减可得：内网路由和筛选节省 4.005s，其余部分合计节省 0.655s，净节省 4.660s；阿里云路由和筛选节省 2.406s，其余部分合计增加 0.415s，净节省 1.991s。这是耗时的分项核算，不是对所有差异的独立因果估计。

### 两套服务接入 D3 后的耗时差异

以下两列均为接入相同 D3 服务后的结果，各 60 次请求；“其余环节”包括路由、充分性检查、生成及其他服务端开销和 HTTP/传输差额。

| 环节 | 内网 Qwen + D3 | 阿里云 Qwen + D3 | 阿里云减内网 |
|---|---:|---:|---:|
| 片段筛选及调度 | 1.231s | 1.233s | +0.002s |
| 问题分解 | 1.155s | 2.005s | +0.850s |
| 检索 | 1.322s | 1.915s | +0.593s |
| 其余环节 | 2.385s | 2.452s | +0.067s |
| 完整问答 | 6.092s | 7.605s | +1.513s |

问题分解与检索合计相差 1.443s，占完整问答差额的 95.4%。它们使用主 LLM 或包含主 LLM 调用，并未被 D3 替换。两组的问题分解调用数均为 74，检索节点也均执行 74 次；轮次数相同，不能用阿里云组多跑了检索来解释这部分差额。

问题分解单次模型调用的平均耗时分别为 0.932s、1.621s；记录的平均输出分别为 110.8、191.6 token。token 数采用各服务返回的用量统计，未统一分词，只用于提示生成量的差异，不作为吞吐指标。这里涉及不同模型、中间结果与服务配置，不能将全部时间差直接归为推理硬件或网络更慢。检索节点内还有并发的模型调用及检索工作，同样应采用节点实际经过时间，不能累加所有子调用时长作为解释。

原流程中阿里云组的 LLM 片段筛选比内网组少用 1.750s，而整次问答少用 1.156s，其余环节合计已多用约 0.594s。换成同一个 D3 后，筛选耗时几乎一致，原有优势不再存在，其余环节的差异决定了接入后的绝对耗时。这个结果解释了两组先后顺序的变化，并不否定两组各自接入 D3 后均有提速。

## 答案与引用评阅

评阅前确定目标条文、核心要点和无答案题标准，评阅时隐藏配置标签。由同一个 AI 助手依据条文和返回材料作判断，没有独立人工复核。问题、答案及有序引用内容完全相同的记录复用已核对的评阅，不能将重复次数视为独立复核次数。

- **核心符合预期**：答出所问的核心事实；无答案题则正确承认现有知识库证据不足。此项不保证补充说法和条号全部正确。
- **严格通过**：核心符合预期，需要依据的内容有证据支持，未添加无依据的信息，且返回的引用片段均有用。无答案题正确拒答时可以没有引用。
- **含无关引用**：返回引用中至少有一条既不支持所问内容，也不提供必要背景。按请求计数，不是引用片段数。

| 主 LLM | 配置 | 核心符合预期 | 严格通过 | 含无关引用 |
|---|---|---:|---:|---:|
| 内网 Qwen | LLM 模式 | 53/60 | 34/60 | 17/60 |
| 内网 Qwen | 接入 D3 | 54/60 | 42/60 | 4/60 |
| 阿里云 Qwen | LLM 模式 | 57/60 | 52/60 | 0/60 |
| 阿里云 Qwen | 接入 D3 | 60/60 | 50/60 | 4/60 |

例如，阿里云 D3 组核心要点均符合预期，但电子认证条件题出现了不必要的检测机构条文，纪律处分题也出现了额外的留党察看条文；另外还有无依据补充等问题。因此，60/60 不能写成“答案准确率 100%”，也不能据此声称质量与基线等同。内网组改善与阿里云组的取舍应同时呈现。

本评阅以测试知识库所收录的法规版本为准，不构成对现行法律的权威解释。对严格标准或个别判断有异议时，可根据公开的答案、引用及评阅理由重新标注；目前的计数是该套标准下的 AI 评阅结果。

## 材料与离线核对

| 文件 | 内容 |
|---|---|
| [results.json](results.json) | 配置、30 道题目及评阅范围、240 次请求、3,388 条模型调用计时、答案、返回引用与评阅理由 |
| [requests.csv](requests.csv) | 每次问答的耗时、阶段拆分、回退及质量标签，便于自行统计 |
| [summary.json](summary.json) | 正文和附录表格对应的未取整汇总值 |
| [sha256.json](sha256.json) | 上述三个数据文件的 SHA256 |
| [verify.py](verify.py) | 仅使用 Python 标准库的离线核算脚本 |

在仓库根目录运行，无需网络、GPU 或模型凭据：

```sh
python3 docs/articles/2026-10-20-decision-agentic-rag/e2e/verify.py
```

脚本从节点和模型调用计时重算阶段耗时，再核对均值、中位数、分轮结果、质量标签计数与 CSV，并检查数据文件摘要。它验证数字与记录是否一致，不验证模型评阅的语义判断，也不代替对原服务器环境的独立审计。

发布副本移除了服务地址、鉴权信息、租户标识、内部文档与片段标识。返回的 20 段法规原文按内容摘要编号，供核对答案依据；它们来自《商用密码管理条例》《中国共产党纪律处分条例》《反恐怖主义法》《刑法》《治安管理处罚法》的测试文档，并非完整知识库。未发布完整候选池、知识库索引和私有应用实现，因此这些材料支持离线核算与答案复核，不意味着可以一键重跑全部端到端实验。
